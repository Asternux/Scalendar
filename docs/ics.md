# ICS Export（M7）

M7 输出 RFC 5545 兼容的 `.ics` 文件，可通过 Windows 文件传输或邮件发送到 iPhone/iPad，再由系统日历导入。`.scalendar` 仍然是唯一真相源，ICS 是一次性导出结果。

## 事件策略

每个实际课程 occurrence 生成一个 `VEVENT`：

- `UID` 由稳定 Course UUID、上课日期和起止节次组成，课程编辑或重复导出时不会依赖 Excel 行号。
- `DTSTART`、`DTEND` 使用 `Asia/Shanghai` 时区，并读取项目中的节次时间。
- 每周、单周、双周和自定义周次先展开为实际日期，因此不依赖日历客户端对复杂 RRULE 的支持。
- `SUMMARY` 使用课程名称；教师和备注进入 `DESCRIPTION`。
- `LOCATION` 优先使用用户确认的原始地点文本，否则组合学校、校区、教学楼和教室。

## 地点安全策略

当前只输出普通文本 `LOCATION`，不输出 `GEO` 或 `X-APPLE-STRUCTURED-LOCATION`。这样可以避免 iPhone/iPad 根据“二教”“体育馆”等同名文本自动猜测到错误地点。未来如果增加位置能力，应只在用户明确确认经纬度后再写入结构化位置字段，并保留原始地点文本。

## 当前边界

M7 不发送邮件、不调用地图服务、不创建日历账户或订阅源，也不负责自动推送。用户仍需通过文件选择、分享或邮件附件把 ICS 交给手机端。后续推送模块应复用这里的 ICS 生成器，而不是重新实现课程日期计算。
